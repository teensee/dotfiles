Отрефактори корневой CLAUDE.md проекта в стиле progressive disclosure: в корне остаётся только то,
что релевантно _каждой_ задаче, всё остальное переезжает в тематические файлы, подгружаемые по
требованию.

Работай в этом порядке и останавливайся, где указано.

1. Сначала противоречия. Перечисли все взаимоисключающие инструкции. Для каждой покажи обе версии и
   спроси, какую оставить — дождись ответа, прежде чем продолжать.

2. В корне оставь только суть:
   - Одно предложение об описании проекта
   - Менеджер зависимостей/пакетов и нестандартный способ его вызова
   - Команды build/test/lint/static-analysis, которые агент не угадает по репозиторию
   - Жёсткие правила, применимые к любому изменению
   Стремись уложить корневой файл в ~50 строк, чтобы он читался с одного взгляда.

3. Всё остальное группируй по темам (адаптируй категории под стек — конвенции фреймворка/домена,
   тестирование, слой данных, git-workflow, деплой). Один файл — одна связная тема.

4. Выведи результат:
   - Структуру `docs/ai/` (какие файлы создать)
   - Минимальный корневой CLAUDE.md со ссылками на каждый тематический файл и коротким «читай это,
     когда…» для каждой ссылки
   - Полное содержимое каждого тематического файла. Команды, пути и правила сохраняй дословно.

5. Отметь на удаление (перечисли, дождись подтверждения — не удаляй молча) всё, что дублирует
   очевидные для агента вещи, слишком расплывчато, чтобы на него можно было опереться, или является
   генеричным филлером («пиши чистый код», «следуй best practices»).

Ограничения: реорганизуй только то, что уже есть в файле — не выдумывай конвенции, которых там нет.
Оставайся tool-agnostic по стеку — определяй его из содержимого файла.
