Прочитай файлы task.md, task-research.md и task-plan.md в корне проекта.

Твоя задача — реализовать план. Следуй task-plan.md ТОЧНО. Если план требует корректировки — сначала
скажи об этом и дождись подтверждения.

## Делегирование

Делегируй реализацию специализированным агентам по типу работы:

- PHP/Symfony-код, Doctrine, Messenger → symfony-dev агент
- Go-код, RabbitMQ, HTTP → go-dev агент
- Python-код, FastAPI, Django → python-pro агент
- Rust-код → rust-engineer агент
- Zig-код → zig-dev агент
- SQL, миграции, индексы → dba агент
- Docker, CI/CD, bash-скрипты → devops агент
- Написание тестов → test-writer агент
- Баги, падения, race conditions — если что-то ломается в процессе → debugger агент

Один шаг плана = один агент. Если шаг затрагивает несколько областей — раздели на подзадачи и
делегируй каждую нужному агенту.

Шаги плана, затрагивающие БД (SQL, миграции, индексы, `EXPLAIN ANALYZE`, схемы) — ВСЕГДА делегируй
агенту `dba`. Не пиши SQL сам через bash/psql: dba использует Postgres MCP-инструменты, когда сервер
включён в проекте (см. CLAUDE.md).

## Правила

1. Выполняй шаги из task-plan.md последовательно
2. После каждого значимого шага — краткий статус что сделано
3. Следуй стилю и паттернам существующего кода
4. Запусти тесты после реализации
5. Если тесты падают — почини

## Результат

После завершения создай/обнови файл task-log.md:

```text
# Лог реализации

## Дата
(timestamp)

## Созданные файлы
- path/to/new/file — описание

## Изменённые файлы
- path/to/changed/file — что изменено

## Миграции
- (если были)

## Тесты
- Результат прогона: OK / FAIL
- Какие тесты добавлены/изменены

## Заметки
(Если отступил от плана — почему)
```

После завершения скажи: "Реализация завершена → task-log.md. Проверь изменения через git diff и
запускай /review."
