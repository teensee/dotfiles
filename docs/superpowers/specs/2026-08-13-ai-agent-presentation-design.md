# Дизайн: мини-презентация «AI-агент и харнесс opencode»

Дата: 2026-08-13 Формат: неформальный рассказ паре коллег, до 30 минут, с живым демо в терминале. Язык: русский.

## Цель

Показать на практике, чем работа с AI-агентом отличается от «пообщаться с чатом», и из чего состоит харнесс (opencode):
субагенты, скиллы, slash-команды, память (AGENTS.md + docs), MCP. Демо — на готовых конфигах из репо `~/.dotfiles`, без
создания чего-либо с нуля.

## Ключевой тейквей

Агент силён не сам по себе, а в связке с процессом и инструментами: правильный харнесс превращает LLM из болтуна в
исполнителя.

## Структура

### 1. Вступление — 2 мин

Цель блока: задать рамку — почему чат недостаточен.

- LLM по умолчанию: нет доступа к коду, нет памяти о репо, нет дисциплины выполнения
- Харнесс = инструменты (терминал, файлы, grep) + память (docs, AGENTS.md) + процесс (команды, субагенты, скиллы)
- Реплика: «Сам по себе ИИ генерирует текст. Харнесс даёт ему руки, память и регламент»

### 2. Путь и мотивация — 3 мин

Цель: показать, что это не «внезапная магия», а результат итераций.

- Старт с Claude Code → миграция на opencode (git log: «claude -> opencode migration»)
- Что хотелось:
  - воспроизводимый конфиг в репо (dotfiles), а не разовые настройки
  - контроль над процессом: ресёрч → план → реализация → ревью
  - дешёвые модели на рутине, дорогие — только на сложном
  - специализация вместо «один агент на всё»
- Тезис: харнесс эволюционирует вместе с практикой (rework-agents.md как чеклист доработок)

### 3. Анатомия харнесса — демо (~14 мин) — ядро

Цель блока: разобрать по слоям, с показом реальных файлов из `~/.dotfiles/opencode/` (как демо-стенд) и
`~/.config/opencode`.

#### 3.1 Субагенты — ~4 мин

- Показать `opencode/agent/` — 13 специализаций: research, architect, code-reviewer, debugger, security-auditor
  (reasoning), dba, devops, go-dev, python-pro, rust-engineer, symfony-dev, zig-dev, test-writer
- Разобрать анатомию файла агента на примере `agent/architect.md`:
  - frontmatter: description, mode (subagent), model, permissions (read-only на код, право писать только в
    `task-plan.md`)
  - промпт: методология + чеклист качества + формат результата
  - вывод: «агент = не новый промпт, а роль + права + регламент»
- Ключевой приём: права доступа — агент-архитектор физически не может испортить код
- Модели на роль: reasoning-агенты на `deepseek-v4-pro`, имплементеры и test-writer на flash, dba на glm-5

#### 3.2 Slash-команды — ~3 мин

- Показать `opencode/commands/`: /res, /plan, /go, /review, /clean
- Пайплайн (ключевая картинка доклада):
  `/res (research) → /plan (architect) → /go (реализация делегированием) → /review (code-reviewer)` артефакты: task.md →
  task-research.md → task-plan.md → diff + отчёт
- Показать `commands/plan.md`: короткий промпт, который ссылается на system prompt агента — команда как «кнопка запуска»
- Смысл: большая задача декомпозируется на шаги, каждый шаг проверяем человеком

#### 3.3 Скиллы — ~3 мин

- `opencode/skills/` — вендоренные superpowers (vendored локально, без плагин-зависимости)
- Примеры: brainstorming, writing-plans, test-driven-development, systematic-debugging, using-git-worktrees
- Как работают: скилл загружается в контекст при совпадении задачи — «навык с регламентом», а не просто совет
- Механика: срабатывают по описанию; для презентации достаточно показать структуру SKILL.md (когда применять, чеклист,
  процесс)
- Нюанс: версия скиллов фиксируется в репо — воспроизводимость поведения

#### 3.4 Память агента: AGENTS.md + topic-docs — ~2 мин

- `AGENTS.md` — контракт: команды, как добавлять конфиги, обязательство синхронизировать docs
- `.opencode/docs/ai/`: architecture.md, tools.md, workflow.md, git.md — «как устроен этот репо», читаются агентом перед
  работой
- Тезис: харнесс — это ещё и документация; агент силён настолько, насколько точна его память (привет «грабли» из
  блока 5)

#### 3.5 MCP codegraph — ~2 мин

- MCP-сервер codegraph: SQLite-граф символов кода — ответы «с каким кодом связана сущность» без грепа
- Демо-эффект: один вызов `codegraph_explore` вместо grep + чтение файлов
- Тезис: MCP расширяет «органы чувств» агента за пределы файлов

#### 3.6 Конфиг — ~1 мин (кратко)

- `opencode.jsonc`: провайдер (vesna, VESNA_API_KEY), модель по умолчанию, LSP, git-permission (деструктивные
  git-команды запрещены)
- `tui.jsonc`: vim-подобный скролл — «интерфейс под свой вкус»
- Без dotbot/symlinks — вне темы агентов

### 4. Применение — 7 мин

Цель: показать цикл в действии и подтвердить ценность из практики.

- Короткое живое демо: маленькая задача в `~/.dotfiles` (например, добавление алиаса или команды) — пройти /res → /plan
  → /go → /review по-настоящему, показывая артефакты task-*.md
- Примеры из практики:
  - рефакторинг агентов: введение ролей + модели на роль (реализация стала быстрее/дешевле)
  - «so much changes» коммиты как следствие больших сессий — почему пайплайн это лечит
  - автономный ресёрч кодовой базы (research) перед планом — агент приносит факты, человек решает
- Честно: где агент хорошо (обзоры кода, рефакторинги, изучение незнакомой базы), где плохо (изобретение API на пустом
  месте, длинные сессии без плана)

### 5. Практика и грабли — 3 мин

Цель: снять розовые очки, дать применимые советы.

- AGENTS.md должен быть точным: docs обязаны совпадать с репо — иначе агент действует по устаревшей картине
- Не давать агенту всё сразу: одну большую задачу без плана → хаос в диффе; план → атомарные шаги
- Права доступа — защита от самого агента (architect не может писать код)
- Дёшево ≠ плохо: рутина на flash-моделях, reasoning на pro — цена контролируется ролью
- Скиллы — не панацея: они работают, когда задача им соответствует; не пытаться «засунуть» всё в скиллы

### 6. Вывод — 1 мин

- Харнесс превращает LLM из генератора текста в участника процесса: руки (инструменты), память (docs), регламент
  (команды/скиллы/права)
- Окупается на дистанции: воспроизводимо, контролируемо, дёшево за счёт моделей на роль
- Приглашение: открыть конфиги, спросить, что показать подробнее

## Материалы для выступления
