Прочитай файлы task.md и task-research.md в корне проекта.

Твоя задача — составить детальный план реализации с примерами структуры кода.

## Делегирование

Для составления плана привлекай специализированных агентов через Task tool:
- PHP/Symfony-код, Doctrine, Messenger → symfony-dev
- Go-код, RabbitMQ, HTTP → go-dev
- SQL, миграции, индексы → dba
- Docker, CI/CD, bash-скрипты → devops

Агент помогает определить правильную структуру: интерфейсы, сигнатуры методов, схемы SQL, конфигурации — чтобы при реализации не было неопределённости.

## Шаги

1. Определи стек по task-research.md
2. Для каждого сложного компонента задачи — запроси у соответствующего агента эскиз структуры
3. На основе ответов составь единый план

## Результат

Создай файл task-plan.md в корне проекта:

```
# План реализации

## Подход
(Краткое описание выбранного подхода и почему)

## Шаги

### 1. [Название шага]
- Файл: path/to/file
- Действие: создать / изменить / удалить
- Детали: что конкретно сделать
- Структура (если нужна):
  ```язык
  // интерфейс / сигнатура / схема — не реализация
  ```

### 2. [Следующий шаг]
...

## Миграции БД
(SQL-структура: таблицы, индексы, constraints)

## Тесты
- Какие тест-кейсы добавить/изменить
- Happy path
- Edge cases
- Error cases

## Риски
(Что может пойти не так, на что обратить внимание)
```

В структурных примерах пиши только скелет: интерфейсы, сигнатуры, схемы — не реализацию.

После создания файла скажи: "План готов → task-plan.md. Проверь, поправь если нужно, и запускай /go"
