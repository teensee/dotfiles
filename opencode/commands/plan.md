Прочитай файлы task.md и task-research.md в корне проекта.

Твоя задача — составить детальный план реализации. НЕ пиши код реализации.

## Шаги

1. Прочитай task.md и task-research.md
2. Проанализируй затронутые файлы (определены в task-research.md):
   - Изучи существующие паттерны (как устроены похожие хендлеры/сервисы/репозитории)
   - Определи сигнатуры методов, интерфейсы, схемы SQL, которые потребуются
   - Найди конфиги (routes, services, DI) и пойми как добавить новые элементы
3. Для каждого компонента продумай структуру — НО не реализацию

## Правила

- **Только read-операции над кодом** — ты НЕ можешь редактировать файлы проекта
- **Пишешь только task-plan.md** — никаких других записей
- Не делегируй другим агентам — выполняй анализ сам
- В плане указывай только: какие файлы создать/изменить, структуру (интерфейсы/сигнатуры), SQL-схемы, конфиги

## Результат

Создай файл task-plan.md в корне проекта:

```
# План реализации

## Подход
(Краткое описание выбранного подхода и почему)

## Шаги

### 1. [Название шага]
- Файл: path/to/file
- Действие: создать / изменить / удалить
- Детали: что конкретно сделать
- Структура (если нужна):
  ```язык
  // интерфейс / сигнатура / схема — не реализация
  ```

### 2. [Следующий шаг]
...

## Миграции БД
(SQL-структура: таблицы, индексы, constraints)

## Тесты
- Какие тест-кейсы добавить/изменить
- Happy path
- Edge cases
- Error cases

## Риски
(Что может пойти не так, на что обратить внимание)
```

В структурных примерах пиши только скелет: интерфейсы, сигнатуры, схемы — не реализацию.

После создания файла скажи: "План готов → task-plan.md. Проверь, поправь если нужно, и запускай /go"
