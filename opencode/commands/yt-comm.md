# Задача

Определи id задачи из git: `git branch --show-current` (если пусто —
`git rev-parse --abbrev-ref HEAD`), из имени ветки извлеки id по паттерну `[a-z]+-\d+` (например
`compass-3951`). Если id не находится — спроси у пользователя.

# MR по текущей ветке

Попробуй найти MR через GitLab MCP (`gitlab`):

- `gitlab_list_merge_requests` с фильтром `source_branch = текущая ветка`, `state = opened|merged`,
  без `project_id` (по всем доступным проектам);
- из каждого MR возьми путь проекта и iid.

Если MCP `gitlab` недоступен или MR не найдены — спроси у пользователя ссылки на MR.

# Нормализация

Каждую ссылку MR приведи к виду `.../-/merge_requests/<iid>/diffs` — чтобы открывался сразу дифф.

# Формат комментария

Единый вид, группы разделяются строкой `___`:

```
HUB-SDK-LIB: <link>
___
SDK1: <link>
SDK2: <link>
___
SERVICE1: <link>
SERVICE2: <link>
```

Группировка: проекты SDK первыми, затем остальные сервисы. Внутри группы — исходный порядок. Писать
с `usesMarkdown: true`.

# Куда писать

Получи комментарии задачи (`youtrack_issue_comments`):

- есть свой комментарий и он последний в списке → обнови через `youtrack_issue_comment_update`:
  объедини списки MR (добавь новые, удали дубликаты по iid, сохрани порядок SDK → сервисы);
- свой комментарий есть, но не последний → создай новый через `youtrack_issue_comment_create`, но
  сначала спроси пользователя: перенести весь список MR в новый комментарий или добавить только
  новые MR;
- своего комментария нет → создай новый со всем списком.

# Поле MR Gitlab

После записи комментария заполни поле задачи «MR Gitlab» основным MR:

1. Основной MR: если MR один — он; если несколько — спроси пользователя, какой основной, показав
   список MR.
2. Значение — та же нормализованная ссылка `.../-/merge_requests/<iid>/diffs`.
3. Текущее значение возьми из `youtrack_get_issue` (`fields["MR Gitlab"]`):
   - пусто → записывай;
   - та же ссылка → ничего не делай;
   - другая ссылка → спроси пользователя, перезаписывать ли.
4. Запиши через `youtrack_set_mr_field`. Если в проекте нет такого поля — сообщи об этом, но не
   считай это провалом команды.

# Текст

Свободный текст из `$ARGUMENTS` добавь в конец комментария.

# Проверка

После записи перечитай `youtrack_issue_comments` и подтверди, что комментарий на месте и ссылки
корректны. Перечитай `youtrack_get_issue` и подтверди, что в поле «MR Gitlab» нужная ссылка.
